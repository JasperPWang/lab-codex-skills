# 新项目接入与跨服务器接续

用于新建实验查看入口、接入新的研究项目，或在另一服务器继续已有项目。目标是得到可操作、可追溯的真实实验页面；不是先批量生成空站点。

## 1. 确认已有事实

先读项目 AGENTS、README、handoff/RoadMap、实验记录和已有可视化文档，查看 Git 状态。确认研究项目与多个方法仓库的归属、当前代码主写入位置、服务主机、允许读取的结果范围和实际查看设备。已知信息从本地配置与定向检查取得，不重新向用户发长问卷。

定位已有页面、查看器、注册器、数据 schema、验证工具和可复用代码。只检查项目指定目录，不扫描所有磁盘或枚举其他科研任务。已有服务先检查，不默认重新启动；本机隧道断开与服务器服务故障分别判断。

确认以下证据后才登记为可用：实际保存的输入/输出及身份、格式内容、完成状态、指标文件与协议、GT 来源、坐标/单位（适用时）。缺失的字段记录未知，不从文件名或相近案例推断。没有结果时先建立接入约定和轻量文档，不下载大型模型或启动推理来填充页面。

## 2. 决定复用方式

优先顺序：

1. 已有查看器可用：在其项目空间接入适配器与数据，不重建网站。
2. 当前主机没有查看器：优先复用已建立的私有代码仓库 [JasperPWang/ResearchGallery](https://github.com/JasperPWang/ResearchGallery)。先读该 checkout 的 README、AGENTS 和 `docs/REUSABLE_SETUP.md`，核对版本与依赖，按实际命令初始化独立数据根目录和节点服务；大资产留原服务器。入口先用独立链接。
3. 现有内核缺少项目能力：先增加数据适配器或所需组件；只有核实已有架构确实不适用、且任务要求独立实现时才新建查看器，不因换服务器重新搭建。

ResearchGallery 代码仓库与本 skill 仓库独立：同步 skill 不等于已安装应用。使用现有 GitHub 授权读取私有仓库，不将 token 写进 URL/配置或把客户端凭据复制到服务器。目标节点无法访问 GitHub 时，可从已授权 checkout 传输固定提交的代码 bundle/archive 并核验提交或摘要，只传代码，不携带私有配置、依赖缓存或实验资产。访问受阻时明确记录，先完成可独立核查的协议/数据工作；不能静默换一套实现或声称已复用。

代码复用需要固定 commit；未提交代码应记录 dirty 状态与构建内容摘要，不能把 release 摘要写成 Git commit。按仓库 README 执行安装/构建、空库初始化、通用注册与便携验证；历史领域适配器和旧部署脚本只在其配置已核实的项目使用。通用注册器的当前格式、栏数和动态能力限制以实际代码为准，已有 schema 字段不自动意味着功能已实现。

共用导航、登记/加载、版本和资源管理；各项目适配实验语义与专属面板。基线、当前方法、消融是方法/run 的关系，不以仓库名硬编码页面栏位。保留既有 ID/URL，项目归属调整须兼容旧链接，不默认迁移原目录。

## 3. 先做真实案例闭环

按真实结果选择需要的能力，而非一次装上全部功能：

| 结果 | 首次接入重点 |
| --- | --- |
| 图像/视频 | 原输入、实际处理输入、结果、可用 GT、对应指标与缺失状态 |
| 静态 Mesh/点云/3DGS | 格式、坐标/尺度与投影来源，实际渲染器和完整性；先按需加载 |
| 动态 Avatar/序列 | 身份、序列、帧/时间映射、相机、动作/驱动条件、缺帧状态；验证播放/seek 同步 |
| WorldModel/rollout | 上下文帧、条件/动作、预测区间、目标帧、种子/采样与视角、时间对齐和评测范围 |

这些是能力选择提示，不是对项目任务的预判。Avatar 可能当前只有静态结果，WorldModel 也可能尚无动作条件；按真实产物实现，并明确当前支持范围。多个随机预测可以并列查看，不能未经定义当成一一对应或只挑最好的一次代表总体。

用一个真实案例打通：适配输出 → 清单校验 → 受控登记 → 页面展示 → 原始记录核对。已有失败或缺失案例时再检验相应状态；不存在的情况用隔离合成 fixture 测试，不伪造成正式研究案例。随后登记本轮约定的样本范围，不自动导出全项目或重新计算全部指标。

## 4. 持久部署与接续

- 代码、导出资产、索引和实验源结果各有明确职责；保持源文件不变，转换产物独立存储。网站数据目录沿用项目约定，不能混入原始 `datasets/` 库或冒充训练用 `data/`。
- 新主机写大文件前核验实际挂载、容量和缓存位置。服务依赖与科研训练环境隔离，复用已核实环境；不擅自变更共享 Docker、安装全局包或启动 GPU 作业。
- 默认只监听 loopback，采用现有 SSH 转发。选空闲端口并记录；不杀占用端口的未知进程。只有需要时启动服务，不自动设开机启动或公网访问。
- 部署代码与发布索引分开验证。发布新的索引前验证全部引用；原子切换完成版本，失败仍可读取原完整版本。不能把部分写入标 ready。
- 记录代码提交/构建摘要、schema 版本、索引 generation 与评测版本。切换只停止命令行/路径与记录一致的本服务进程；索引回退须与代码兼容，不自动清理旧资产或共享依赖。
- 把真实启动、更新登记、停止与验证命令记入项目文档。只有已执行的命令才能标为验证通过；模板中的示例不是现成实现。

## 5. 验收与交接

按修改范围执行项目已有构建/协议/逻辑测试，再检查真实案例。浏览器检查首屏无重型三维加载、正确资产/画面非空、导航与缺失状态；涉及三维则检查相机/投影、完整元素与卸载，涉及动态结果则检查 frame/time 和异步就绪。布局检查桌面与窄屏；性能在实际查看设备测量，不以服务器 HTTP 200 代替。

新页面需要服务时，启动并提供实际可访问 URL；离线纯 HTML 则给文件入口。通过隧道访问时分别记录服务和隧道状态。远端不可达、无图形验证或素材缺失时说明已完成与未验证范围，不宣称部署/验收成功。

使用 `assets/visualization.md` 填写项目接入信息，或合并到已有同职责文件；在项目入口/handoff 添加链接。当前数量由索引计算，历史测量不覆盖当前状态。发现失败现象记录“案例/版本/视角 → 观察 → 假设 → 待验证”，实验结论仍由既有研究报告维护。
