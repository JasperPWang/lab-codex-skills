# 以 Project 为入口的科研工作流

目标是让同一个项目的问题、相关工作、baseline、数据和实验能互相追溯，并让新会话快速接续。适用于新建项目及给已有项目补缺。先查看项目现有入口、代码仓库、Notion/其他文档、数据目录和运行记录；复用已有名称和页面 ID，不默认重排或迁移项目。

结构设计参考 [skJack/research-workflow](https://github.com/skJack/research-workflow/tree/14c882df49a7991b9833f2ff416e4dfd38668827)（2026-10-15 检查的 commit）。借鉴单一职责、交接、相关文献、baseline 复现、固定测评协议与数据说明；以下规则和模板为本工作流的适配，不安装或执行上游脚本。原始论文/PDF/LaTeX 下载件保持原样；解析、注释清理或旧稿隔离只作用于派生副本。图片可从官方 HTML、PDF 或源码资产获取，遵循已有 paper skills 的来源核验。

## 项目入口与存放职责

项目入口简述研究问题、目标/边界、当前假设、最近状态和下一步，并链接以下模块。它可以是已有 Notion 项目页、其他既有平台入口或明确指定的本地文档。未指定新的文档落点时，沿用现有项目；新实验报告默认 Notion。创建平台文档前走 `research-doc-workflow` 和对应适配器。本次只更新 skill 时，不自行创建平台页面或为整个 vault 建科研项目骨架。

| 模块 | 职责 | 与已有结构的兼容方式 |
| --- | --- | --- |
| Related Work | 项目相关文献矩阵、竞争方法、证据与研究空缺 | 复用现有文献页/卡片，通过链接建立项目关系 |
| Reproduction | 关键 baseline 的复现清单、进度与可信程度 | 复用已有 GRAFT 等方法页；在此建索引，不复制或移动报告 |
| Datasets | 原始数据版本、项目使用范围、预处理与 split | 数据说明指向数据盘原始目录及项目派生目录 |
| Ideas / Brainstorm | 假设、推导来源、反证条件、待做 MVE | 延续现有笔记；通过复现或文献证据修订假设 |
| Evaluation | 固定且可版本化的测评协议 | 本地 `experiment/evaluation.md` 或既有协议页，确定一个权威位置 |
| Experiments | 每轮实验计划、结果与判断 | 延用 Notion 实验报告；本地如需结果表，只维护可追溯的运行索引 |
| Visualization | 当前项目的实验入口、版本对照、过程证据与失败案例检查 | 使用 `research-viewer`；复用查看器代码，各项目保留独立数据与适配器，入口链接实验报告 |
| Handoff / RoadMap | 当前执行状态与后续优先级 | `handoff.md` 是短期接续，`RoadMap.md` 是路线图，两者链接报告 |

新代码项目的可选本地组织如下；只在实际需要时补缺，已有同职责文件继续使用。保留所有现有 AGENTS 指令（包括额度重置限制），只追加必要导航，不能用模板覆盖。下列目录放轻量文档和脚本，不承载真实大数据或模型。

```text
<project>/
  AGENTS.md                  # 项目问题、边界、目录和权威文档入口
  handoff.md                 # 会话接续
  RoadMap.md                 # 已有路线图
  related_work/README.md     # 文献索引；完整卡片可在项目文献页
  reproduction/README.md     # baseline 清单及方法页链接
  reproduction/<method>/    # 方法适配配置、启动/评测命令、报告链接
  dataset.md                 # 项目使用的数据版本及预处理说明
  experiment/evaluation.md  # 版本化的评价契约（若本地为权威）
  experiment/results.md     # 可选运行索引，链接 Notion 和 metrics.json
```

代码仓库/各 baseline checkout 的目录沿用项目约定，不强制放进 `reproduction/`；大数据、下载缓存、权重及渲染/训练产物放实际核验的数据盘。原始数据与项目副本的规范见 [`dataset-storage.md`](../../research-dev-standards/references/dataset-storage.md)。

## 实验可视化随项目推进

研究项目按研究目标划分，不按仓库或服务器划分；同一项目可以包含多个 baseline/方法仓库。重要项目继续推进并有需要检查的基线/实验结果时，使用 [`research-viewer`](../../research-viewer/SKILL.md) 检查已有入口，复用统一查看器并建立项目独立空间。先登记本轮真实案例，再扩大覆盖；不提前批量为所有项目建站。

采用一个总入口导航，各项目页面、服务与资产可在不同服务器，早期链接即可，不以中央网关或资产搬迁作为前置条件。当前项目可按 [`visualization.md`](../../research-viewer/assets/visualization.md) 记录实际入口、命令、协议与验证范围，已有同职责文档继续使用。关键实验报告/handoff 链接案例及 run/索引版本，区分登记数量与有效评测总体；未接入或未检查的部分如实说明。

## 从观察到问题的入口

观察到失败案例、异常结果或想改进方法时，先按 [`observation-to-problem.md`](observation-to-problem.md) 核验现象、查相关工作、分析可能原因并进行必要诊断，再选择具体方案。Related Work 核查是方案设计前的必要步骤；原因不清楚时先做诊断实验。复现暴露的失败也走这个入口，不能从失败样本直接跳到加模块。

## Related Work：文献怎样影响当前项目

本节为用户于 2026-10-18 确认的 **Related Work 整理规范 v1.0**，是目录命名、原始材料保存、补充材料核查和代码收集的权威规则。今后新入库或明确要求补齐的论文默认执行；已有目录不自动迁移。本规范的确认不自动触发历史文献补下载、论文翻译或 baseline 复现。

### 本地文献目录与文件命名

新增本地论文材料按以下规则整理；分类与论文完整标题优先可读性，不用缩写、slug 或通用的 `paper.pdf` 代替。既有文献不因更新规范自动批量重命名或搬迁，用户要求迁移时再同步修正索引和已有链接。

```text
related_work/
  README.md                         # 总索引、材料状态及项目相关性
  <Category Full Name>/
    <YYYY> - <Full Paper Title>/
      <Full Paper Title>.pdf
      <Full Paper Title> - Supplementary Material.pdf
      source/
        <arXiv-ID>v<N>.tar.gz
        extracted/
          <原始源码包中的文件与子目录>
        derived/                    # 可选：清洗或解析后的派生副本
      supplementary/                # 可选：补充视频、其他附件及原包
      code/
        <official-repository-name>/
          <下载的官方方法代码>
```

上图是命名占位示例，不实际创建尖括号名称；补充 PDF、`source/`、`code/` 仅在确有对应材料时保存，`derived/` 和 `supplementary/` 仅在实际需要时创建，不创建占位空文件/目录。压缩包扩展名遵循真实格式，不将所有来源强行改为 `.tar.gz`。

- **分类文件夹用标准术语全称**：如 `Human Mesh Recovery`，不用 `HMR`、拼音或自造简称；保留正常空格，不为便于命令行而改成下划线或连字符缩写。只建当前收藏确有需要的分类，不预建空分类树。
- **论文文件夹用 `YYYY - 完整论文标题`**：以对应版本的官方标题为准，包括标题中本来存在的方法简称和完整副标题；不能只用方法名或 arXiv ID。年份优先采用已核验的正式发表年份，未正式发表时用预印本首次公开年份，并在既有索引注明。未核实年份先标 `Year Unknown`，不猜测，也不采用下载年份。
- **PDF 文件用 `完整论文标题.pdf`**：与所在目录的标题部分一致，保留官方标题的词序、大小写和副标题，不自行翻译或缩短。路径不安全或跨平台不兼容的字符（如 `/`、`:`）仅在文件名中替换为 ` - `，去掉末尾空格/句点；索引仍记录准确官方标题。读写含空格路径时正确引用，不据此改用简称。
- **同名或多版本不覆盖**：按官方标识核查是否同一论文；同名不同论文可在目录末尾加 arXiv ID/DOI 的安全标识。同一论文保留多个版本时，在相应 PDF 完整标题后加 ` - arXiv vN` 或 ` - Published`，源码包及解压目录按同一版本分开，并在索引注明当前阅读版本，避免跨版本混引。
- **`source/` 同时保留源码包与原样解压内容**：原始下载包直接放其中，优先保留有辨识度的原名；原名不明确时用带官方标识/版本的名称。解压到 `source/extracted/`，保持包内目录、宏定义和图片资产，不在原样解压目录中剥注释、删除或移动旧稿。需要清洗/解析时另建派生副本（如 `source/derived/`），记录所用原包与处理方式，不能处理完就删原包。无公开源码或未获取成功时如实标注，不创建空包或假装已下载。
- **区分论文源码和方法代码**：`source/` 存论文 LaTeX/投稿源码，`code/` 存随文收藏的官方方法代码快照。真正开展复现的工作副本、权重及环境仍沿用 Reproduction 和数据盘约定，不在收藏快照中直接改代码、安装或训练。
- **索引指向材料，不重复收藏**：在既有 Related Work 索引记录分类、准确标题、年份依据、官方标识/来源、PDF/源码实际版本与本地路径。跨多个主题的论文选一个主分类，其他分类通过索引引用，不重复维护多份材料；已有论文卡片和精读记录继续链接原位置。

### 补充材料核查：每篇入库必做

不能只下载主论文便算材料整理完成。对每篇新入库或被要求补齐材料的论文，主动查找 Supplementary Material / Supplemental / Appendix / Additional Material，包括独立附件及并入正文的附录。

- 核查官方会议/期刊论文页及 HTML、OpenReview 等投稿页的附件、作者项目页，以及存在时的 arXiv 摘要页、完整 PDF 与 LaTeX 包；按已知官方链接追踪 `supp`、`supplementary`、`appendix` 等入口。会议主 PDF 未附附录不能据此判定没有补充材料。
- 找到独立补充 PDF 时，下载到同一论文目录，命名为 `完整论文标题 - Supplementary Material.pdf`；多个附件用官方附件名称或编号区分。有公开补充视频、网页或附件包时也核查并记录；可下载文件存于该论文的 `supplementary/`，保持原件，解压不删除原包。无独立文件时不强造目录；仅网页可访问时保留来源链接及访问状态，不虚称已下载。
- 附录已包含在完整论文 PDF/源码中时，记录所在版本和章节/页码，不要求重复拆出一份 PDF。补充材料与主论文的标识/版本必须对应；正式版和预印本内容不同则分别标注，不能静默混用。
- 在既有索引中记录实际状态：`独立补充材料已获取`、`已含于主文/源码`、`查找后未发现`、`已发现但获取受阻` 或 `尚未核查`，附来源/本地路径、核查日期和必要的已查入口。`查找后未发现` 不等于确定不存在；访问失败、权限限制不能记成无补充材料。`尚未核查` 或获取受阻时，整套材料标为待补齐，不能声称收集完整。

本节要求材料检索与保存，不自动要求完整翻译或深读；用户要求精读时再按 `paper-deep-dive` 将已找到的补充材料纳入完整内容覆盖。

### 开源情况与官方代码下载：每篇入库必做

每篇论文都要核查并说明代码公开情况；有可访问的官方实现时，资料收集默认同时下载代码，不只留下仓库链接。这不要求额外确认，也不等于授权安装依赖、运行仓库脚本或启动复现。

- **先核实官方身份与实际内容**：从论文、项目页、作者/实验室页面追踪仓库，必要时按完整标题、方法名和作者检索。打开仓库检查是否真有对应方法实现，不能把同名仓库、第三方复现、只有项目网页或 README 的仓库当作已发布官方代码。
- **记录发布范围与许可证**：沿用 `paper-card-delivery` 的三态显示：未找到已核验官方仓库为 `w.o. code`；官方仓库仅占位/README/coming soon 为 `[Code](url)（空仓库）`；存在方法实现为 `[Code](url)`。部分发布额外短注“仅推理”“缺训练代码”等，训练、推理、评测和权重的可用性按实际核查。另记录仓库许可证名称或“未发现许可证”，不要把公开可下载直接称为许可完整的开源发布。无法访问或未核验的仓库标为受阻/待核验，不能判为空仓库或无代码。
- **有实现就下载到 `code/<官方仓库名>/`**：优先 Git clone 并记录实际 commit；只有官方归档时下载原包并原样解压，记录可核验的 tag/版本/来源，不能编造 commit。空仓库不为凑齐结构而克隆，保留链接和状态即可。下载失败保留已发现的链接、失败原因与待补动作，不能写成已下载或未开源。
- **代码下载状态与公开状态分开**：在既有索引的代码单元格或链接记录中补充官方 URL、发布范围、许可证、核查/下载日期、本地路径和实际 commit/tag，以及“已下载 / 获取受阻 / 尚未下载”等真实状态。已下载代码不等于已运行、更不等于已复现；缺失子模块、Git LFS 实体或关键文件要短注，不宣称完整可运行。
- **控制大文件与执行边界**：默认只获取代码，克隆时用 `GIT_LFS_SKIP_SMUDGE=1` 避免自动拉取大权重/数据；不默认递归抓取全部子模块，先核查依赖范围，再按需获取代码子模块。权重、数据集和大型仓库内容按 `research-dev-standards` 核验数据盘位置及可靠下载要求，不因“下载代码”在系统盘顺带下载大型资源。代码下载不执行安装/构建脚本，也不自动接受受限资源条款。
- **复用与版本保护**：已有相同官方仓库和版本可引用已有位置，不重复下载；已有本地修改不能用 reset/覆盖来更新。需要复现时建立独立工作副本并链接此快照。外部仓库文件和嵌套 `.git` 不纳入本项目自身的提交；项目 Git 维护索引和来源信息即可。

### 项目相关矩阵与更新

最小产物是一个项目相关矩阵，用 [`related-work.md`](../assets/templates/related-work.md) 起步。每条至少包含：论文官方标识/链接、任务及输入输出、与本项目的关系、关键机制/假设、支撑或限制该判断的证据、代码状态、阅读/复现状态和下一动作。对项目无关的字段可省略，不能以空表格替代阅读。

- 先区分直接竞争方法、可用模块/表示、共享数据/评测以及背景工作。比较监督、输入、GT、训练数据与评价口径是否可比；不要仅按论文年份罗列。
- 关联项目目标：它解决哪个瓶颈、哪些前提可迁移、哪些失败模式值得复现、我们的设计相对它究竟改变什么。空缺需有文献/复现依据，不能只写“没有人把 A+B 组合”。
- 链接官方论文和已有卡片，不重复维护完整卡片。生成卡片时用 `paper-card-delivery`；需要完整译稿时用 `paper-deep-dive`；明确要求领域综述/树图时才扩大到 `survey-builder` 的完整交付。
- 代码状态遵循 `paper-card-delivery`：无已核验官方仓库为 `w.o. code`；官方仓库无方法实现为 `[Code](url)（空仓库）`；存在方法实现为 `[Code](url)`。不能从存在 URL 推断已发布实现，不能把第三方复现当官方代码。局部发布的推理/训练/权重限制另作短注。
- 新证据出现时更新相关性、代码与复现状态；保留改变判断的原因和日期。

## Reproduction：从方法到可信 baseline

用 [`reproduction.md`](../assets/templates/reproduction.md) 为每个拟复现方法维护记录。先选对当前问题最有判别力的 baseline 和一个简单有效对照；不是默认跑完所有近年方法。复现可以与读文献、提假设交替进行；未经代码/数据/测评核验的结果不能直接当作新方法收益的基准。

1. 定义复现目标：论文哪张表/哪个设置，或只做本项目数据上的迁移评测。写清输入输出、数据版本、split、权重、指标、容许偏差、资源上限与停止条件。迁移评测不可称为复现了原论文数字。
2. 核对官方代码状态、commit、许可证/访问条件、预训练模型、数据预处理和评价脚本。无官方实现时标明未复现、第三方复现或自行实现，并记录选择依据与差异。固定依赖和下载资源版本，执行 `research-dev-standards`。
3. 先做最小 smoke test，检查中间数据、坐标/单位、mask/裁剪、身份/帧映射和输出；学习任务按需验证单 batch。记录实际命令、环境和日志，跑通只说明管线可用。
4. 在固定协议下运行目标评测，保存原始逐样本指标、有效/失败样本、原分辨率输出和配置。论文值与实测值并列，解释数据、权重、评价、硬件或适配差异，先排查协议差异再调整方法。
5. 回写失败模式、可以信任的比较范围和下一步假设，并关联 Related Work、Dataset 派生版本及实验报告。交接或发布时再用 `repro-pack` 打包可运行材料。

复现状态明确区分 `待评估`、`准备中`、`smoke 已通过`、`部分复现`、`目标已复现`、`受阻`、`已停止`。只有预定目标/阈值通过且有证据时才标“目标已复现”；推理跑通、单例好看或重新计算论文平均值都不足以替代目标验证。失败和作废结果保留并注明原因。

复现报告仍按 `experiment-report-writing` 写入已有项目的方法页/实验记录，保持预注册和既定章节。Reproduction 页是索引和进度，不另造第二套报告字段。

## Datasets：原始来源到每次运行

原始文件保留与目录级 `README.md` / `manifest.json` 的权威规则在 [`dataset-storage.md`](../../research-dev-standards/references/dataset-storage.md)；无需配置只读权限。项目 `dataset.md` 用 [`dataset.md` 模板](../assets/templates/dataset.md) 记录使用契约：

- 原始数据位置为已核验数据盘的 `datasets/<dataset>/<version-or-snapshot>/`，不增设 `raw/` 层；`projects/<project>/data/<dataset>/<derived-version>/` 放该项目处理好的训练/验证/测试数据。预处理暂存使用项目工作区，不混用这两类目录。
- 名称/版本/来源标识；原始 datasets 位置与 manifest；项目 data 路径、准备暂存目录和派生版本。
- 原始及派生目录结构、样本单位、字段/格式、图像分辨率、坐标系/单位、相机/标注/GT 的含义和可用性（按任务填写）。
- 下载/验证、独立复制或解压、预处理、样本索引生成的实际命令；脚本 commit、配置、过滤/去重、前后样本数、已知损坏/缺失。
- 官方 train/val/test 划分及固定样本列表/哈希；自建 split 时说明要泛化的维度并按对应被试/序列/场景/来源等分组，不能把相邻帧泄漏至测试集。官方 benchmark 协议优先；不笼统禁止所有随机样本划分。
- 对不同方法的格式转换单独版本化，说明哪些相同、哪些不同及对公平性的影响。派生 manifest 链接原始 manifest 和预处理版本，使每个 run 都能定位同一份数据。

原始目录只作为校验、独立复制/解压或生成派生数据的读取来源；项目训练/评测不直接把它作为工作目录。禁止用软链接或硬链接冒充项目副本。不得因预处理完成、空间不足或换方法而删除源包。

## 固定 Evaluation 与研究循环

用 [`evaluation.md`](../assets/templates/evaluation.md) 固定任务、数据/split、GT/对齐、指标定义/方向/单位、聚合方式、无效样本处理、评价脚本版本和定性样本规则。对 CV/3D 项目按需说明裁剪、分辨率、相机/坐标、尺度和刚性对齐等约定。比较同一协议版本的结果；改变协议时新增版本并重算所需 baseline，保留旧结果及适用范围。

每轮先固定假设和 MVE 判据，再运行、评价、检查原始输出并更新判断。所有实验有稳定 run ID；失败/停止/作废也可追溯。Notion 报告是实验叙述权威；`results.md` 如存在只维护 run ID、改动、协议/数据版本、状态、metrics/产物及报告链接，数字尽量由原始指标生成，不手抄第二套结论。日期可作为 ID 的一部分，但不能代替改动含义与配置标识。

在既有 run 索引/报告中链接直接来源的 baseline 或父 run，并写明本次关键改动；不要求建立实验树系统。分开判断“执行是否有效”和“结果支持什么科学结论”，失败执行不能当作反驳假说。重复实验按随机性与结论风险决定，不固定种子数；汇总保留各次结果、样本量和波动，不能只选最好一次。汇总图、caption 和正文结论须能回溯到同一批有效 run、原始指标与评价协议。

`brainstorm` 记录现象证据、相关工作及已有解法、可能原因、诊断结果、问题价值、改进假设和下一次 MVE；不要求所有想法先完成复现才可讨论，但研究性改进在选定方案前必须完成针对性相关工作核查。每次重要进展/暂停或交接前更新 [`handoff.md`](../assets/templates/handoff.md)：当前任务、已验证内容、阻塞、活跃 tmux/job、准确路径和下一条可执行动作；不把正在运行的任务写成完成。

## 在现有项目中补缺

先列一张职责映射：当前页面/文件 -> 上述模块 -> 缺什么。优先补已有页面中的索引/字段；新建模块必须连回项目入口。不要在项目页之外额外建立平行项目，也不要为统一英文命名重命名已有 `Exp.`、方法页或数据页。

完成后抽查一条真实链路：项目问题 -> 相关论文 -> baseline 代码/复现状态 -> 原始数据 manifest -> 派生数据/预处理 -> 评价协议 -> run/指标/可视化 -> Notion 报告 -> handoff 下一步。未运行的步骤如实标为计划或受阻，不能用空模板声称已有验证。
