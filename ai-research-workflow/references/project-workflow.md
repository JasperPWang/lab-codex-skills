# 以 Project 为入口的科研工作流

目标是让同一个项目的问题、相关工作、baseline、数据和实验能互相追溯，并让新会话快速接续。适用于新建项目及给已有项目补缺。先查看项目现有入口、代码仓库、Notion/其他文档、数据目录和运行记录；复用已有名称和页面 ID，不默认重排或迁移项目。

结构设计参考 [skJack/research-workflow](https://github.com/skJack/research-workflow/tree/14c882df49a7991b9833f2ff416e4dfd38668827)（2026-10-15 检查的 commit）。借鉴单一职责、交接、相关文献、baseline 复现、固定测评协议与数据说明；以下规则和模板为本工作流的适配，不安装或执行上游脚本。原始论文/PDF/LaTeX 下载件保持原样；解析、注释清理或旧稿隔离只作用于派生副本。图片可从官方 HTML、PDF 或源码资产获取，遵循已有 paper skills 的来源核验。

## 项目入口与存放职责

项目入口简述研究问题、目标/边界、当前假设、最近状态和下一步，并链接以下模块。它可以是已有 Notion 项目页、其他既有平台入口或明确指定的本地文档。未指定新的文档落点时，沿用现有项目；新实验报告默认 Notion。创建平台文档前走 `research-doc-workflow` 和对应适配器。本次只更新 skill 时，不自行创建平台页面或为整个 vault 建科研项目骨架。

| 模块 | 职责 | 与已有结构的兼容方式 |
| --- | --- | --- |
| Related Work | 项目相关文献矩阵、竞争方法、证据与研究空缺 | 复用现有文献页/卡片，通过链接建立项目关系 |
| Reproduction | 关键 baseline 的复现清单、进度与可信程度 | 复用已有 GRAFT 等方法页；在此建索引，不复制或移动报告 |
| Datasets | 原始数据版本、项目使用范围、预处理与 split | 数据说明指向数据盘原始目录及项目派生目录 |
| Ideas / Brainstorm | 假设、推导来源、反证条件、待做 MVE | 延续现有笔记；通过复现或文献证据修订假设 |
| Evaluation | 固定且可版本化的测评协议 | 本地 `experiment/evaluation.md` 或既有协议页，确定一个权威位置 |
| Experiments | 每轮实验计划、结果与判断 | 延用 Notion 实验报告；本地如需结果表，只维护可追溯的运行索引 |
| Handoff / RoadMap | 当前执行状态与后续优先级 | `handoff.md` 是短期接续，`RoadMap.md` 是路线图，两者链接报告 |

新代码项目的可选本地组织如下；只在实际需要时补缺，已有同职责文件继续使用。保留所有现有 AGENTS 指令（包括额度重置限制），只追加必要导航，不能用模板覆盖。下列目录放轻量文档和脚本，不承载真实大数据或模型。

```text
<project>/
  AGENTS.md                  # 项目问题、边界、目录和权威文档入口
  handoff.md                 # 会话接续
  RoadMap.md                 # 已有路线图
  related_work/README.md     # 文献索引；完整卡片可在项目文献页
  reproduction/README.md     # baseline 清单及方法页链接
  reproduction/<method>/    # 方法适配配置、启动/评测命令、报告链接
  dataset.md                 # 项目使用的数据版本及预处理说明
  experiment/evaluation.md  # 版本化的评价契约（若本地为权威）
  experiment/results.md     # 可选运行索引，链接 Notion 和 metrics.json
```

代码仓库/各 baseline checkout 的目录沿用项目约定，不强制放进 `reproduction/`；大数据、下载缓存、权重及渲染/训练产物放实际核验的数据盘。原始数据与项目副本的规范见 [`dataset-storage.md`](../../research-dev-standards/references/dataset-storage.md)。

## Related Work：文献怎样影响当前项目

最小产物是一个项目相关矩阵，用 [`related-work.md`](../assets/templates/related-work.md) 起步。每条至少包含：论文官方标识/链接、任务及输入输出、与本项目的关系、关键机制/假设、支撑或限制该判断的证据、代码状态、阅读/复现状态和下一动作。对项目无关的字段可省略，不能以空表格替代阅读。

- 先区分直接竞争方法、可用模块/表示、共享数据/评测以及背景工作。比较监督、输入、GT、训练数据与评价口径是否可比；不要仅按论文年份罗列。
- 关联项目目标：它解决哪个瓶颈、哪些前提可迁移、哪些失败模式值得复现、我们的设计相对它究竟改变什么。空缺需有文献/复现依据，不能只写“没有人把 A+B 组合”。
- 链接官方论文和已有卡片，不重复维护完整卡片。生成卡片时用 `paper-card-delivery`；需要完整译稿时用 `paper-deep-dive`；明确要求领域综述/树图时才扩大到 `survey-builder` 的完整交付。
- 代码状态遵循 `paper-card-delivery`：无已核验官方仓库为 `w.o. code`；官方仓库无方法实现为 `[Code](url)（空仓库）`；存在方法实现为 `[Code](url)`。不能从存在 URL 推断已发布实现，不能把第三方复现当官方代码。局部发布的推理/训练/权重限制另作短注。
- 新证据出现时更新相关性、代码与复现状态；保留改变判断的原因和日期。

## Reproduction：从方法到可信 baseline

用 [`reproduction.md`](../assets/templates/reproduction.md) 为每个拟复现方法维护记录。先选对当前问题最有判别力的 baseline 和一个简单有效对照；不是默认跑完所有近年方法。复现可以与读文献、提假设交替进行；未经代码/数据/测评核验的结果不能直接当作新方法收益的基准。

1. 定义复现目标：论文哪张表/哪个设置，或只做本项目数据上的迁移评测。写清输入输出、数据版本、split、权重、指标、容许偏差、资源上限与停止条件。迁移评测不可称为复现了原论文数字。
2. 核对官方代码状态、commit、许可证/访问条件、预训练模型、数据预处理和评价脚本。无官方实现时标明未复现、第三方复现或自行实现，并记录选择依据与差异。固定依赖和下载资源版本，执行 `research-dev-standards`。
3. 先做最小 smoke test，检查中间数据、坐标/单位、mask/裁剪、身份/帧映射和输出；学习任务按需验证单 batch。记录实际命令、环境和日志，跑通只说明管线可用。
4. 在固定协议下运行目标评测，保存原始逐样本指标、有效/失败样本、原分辨率输出和配置。论文值与实测值并列，解释数据、权重、评价、硬件或适配差异，先排查协议差异再调整方法。
5. 回写失败模式、可以信任的比较范围和下一步假设，并关联 Related Work、Dataset 派生版本及实验报告。交接或发布时再用 `repro-pack` 打包可运行材料。

复现状态明确区分 `待评估`、`准备中`、`smoke 已通过`、`部分复现`、`目标已复现`、`受阻`、`已停止`。只有预定目标/阈值通过且有证据时才标“目标已复现”；推理跑通、单例好看或重新计算论文平均值都不足以替代目标验证。失败和作废结果保留并注明原因。

复现报告仍按 `experiment-report-writing` 写入已有项目的方法页/实验记录，保持预注册和既定章节。Reproduction 页是索引和进度，不另造第二套报告字段。

## Datasets：原始来源到每次运行

原始文件保留与目录级 `README.md` / `manifest.json` 的权威规则在 [`dataset-storage.md`](../../research-dev-standards/references/dataset-storage.md)；无需配置只读权限。项目 `dataset.md` 用 [`dataset.md` 模板](../assets/templates/dataset.md) 记录使用契约：

- 名称/版本/来源标识；原始库位置与 manifest；本项目副本/独立解压目录和派生版本。
- 原始及派生目录结构、样本单位、字段/格式、图像分辨率、坐标系/单位、相机/标注/GT 的含义和可用性（按任务填写）。
- 下载/验证、独立复制或解压、预处理、样本索引生成的实际命令；脚本 commit、配置、过滤/去重、前后样本数、已知损坏/缺失。
- 官方 train/val/test 划分及固定样本列表/哈希；自建 split 时说明要泛化的维度并按对应被试/序列/场景/来源等分组，不能把相邻帧泄漏至测试集。官方 benchmark 协议优先；不笼统禁止所有随机样本划分。
- 对不同方法的格式转换单独版本化，说明哪些相同、哪些不同及对公平性的影响。派生 manifest 链接原始 manifest 和预处理版本，使每个 run 都能定位同一份数据。

原始目录只作为校验、独立复制/解压或生成派生数据的读取来源；项目训练/评测不直接把它作为工作目录。禁止用软链接或硬链接冒充项目副本。不得因预处理完成、空间不足或换方法而删除源包。

## 固定 Evaluation 与研究循环

用 [`evaluation.md`](../assets/templates/evaluation.md) 固定任务、数据/split、GT/对齐、指标定义/方向/单位、聚合方式、无效样本处理、评价脚本版本和定性样本规则。对 CV/3D 项目按需说明裁剪、分辨率、相机/坐标、尺度和刚性对齐等约定。比较同一协议版本的结果；改变协议时新增版本并重算所需 baseline，保留旧结果及适用范围。

每轮先固定假设和 MVE 判据，再运行、评价、检查原始输出并更新判断。所有实验有稳定 run ID；失败/停止/作废也可追溯。Notion 报告是实验叙述权威；`results.md` 如存在只维护 run ID、改动、协议/数据版本、状态、metrics/产物及报告链接，数字尽量由原始指标生成，不手抄第二套结论。日期可作为 ID 的一部分，但不能代替改动含义与配置标识。

`brainstorm` 记录假设、依据、与最近复现/文献的关系、反证条件和下一次 MVE；不要求所有想法先完成复现才可讨论。每次重要进展/暂停或交接前更新 [`handoff.md`](../assets/templates/handoff.md)：当前任务、已验证内容、阻塞、活跃 tmux/job、准确路径和下一条可执行动作；不把正在运行的任务写成完成。

## 在现有项目中补缺

先列一张职责映射：当前页面/文件 -> 上述模块 -> 缺什么。优先补已有页面中的索引/字段；新建模块必须连回项目入口。不要在项目页之外额外建立平行项目，也不要为统一英文命名重命名已有 `Exp.`、方法页或数据页。

完成后抽查一条真实链路：项目问题 -> 相关论文 -> baseline 代码/复现状态 -> 原始数据 manifest -> 派生数据/预处理 -> 评价协议 -> run/指标/可视化 -> Notion 报告 -> handoff 下一步。未运行的步骤如实标为计划或受阻，不能用空模板声称已有验证。
